# Building the original and Chinese variants

[中文](build-variants.md) · **English** · [English README](../README.en.md)

Both variants use the **Japanese Switch base game 1.0.0**, title ID `0100D7F00FB1A000`. The original Japanese-release assets include English support. This workflow does not support the international executable (`010036E00FB20000`). “Original” means no Chinese resource overlay; executable changes required for the Mac port still apply.

## Outputs and language defaults

| Setting | Original (`original`) | Chinese (`chinese`) |
| --- | --- | --- |
| Assets | Complete, clean Japanese-release RomFS | Same clean RomFS plus your Chinese overlay |
| Game language | English (`en-US`) by default; Japanese/English selectable | `ja`, using the replaced Japanese resources |
| Launcher/menu language | English (`en`) | Simplified Chinese (`zh-Hans`) |
| Bundle ID | `org.nxnative.tgaa.japan.original` | `org.nxnative.tgaa.japan.cn13` |
| Data ID | `0100D7F00FB1A000-original` | `0100D7F00FB1A000-cn13` |
| Chinese version-tag cleanup | Disabled | Applied only when the known tag matches |
| Walkthrough | Not included unless explicitly supplied | Not included unless explicitly supplied |

App display names follow the chosen UI language. Each variant has separate preferences and `~/Library/Application Support/nxnative/<data ID>/`, including `save/`, `save-fresh/`, and temporary button overlays. No existing saves are copied. US/UK language codes do not imply separate English localizations.

Use `--language ja --ui-language en` for Japanese gameplay with an English launcher. You can also select `--ui-language zh-Hans` for the original build or `--ui-language en` for the Chinese build. UI language is selected at build time; the original build's game language can be changed in launch settings. The Chinese build must keep `--language ja` because that is the translated resource slot. UI language does not translate the optional walkthrough.

## Prepare the toolchain and source

Use Python 3.11+, Git, full Xcode/Metal tooling, and the dependencies specified by nxnative at revision `201dfd1280684e9d3ceac8b644236fdac11b6cc2`. The [English README](../README.en.md) includes the exact checkout, three-patch sequence, and profile installation commands. Apply all patches before compiling the native host. A preexisting host binary will not gain the English menu/restart dialog merely by changing its settings JSON.

Follow the pinned checkout's development documentation to extract authorized game data, verify the game build, rewrite its modules, compile shaders, and build the Mac host. This helper does not perform these low-level stages or obtain inputs for you. It invokes the patched Mac packer, which compiles the launcher and packages already-built artifacts.

The profile identifies these module Build IDs:

| Module | Japanese 1.0.0 Build ID |
| --- | --- |
| `main` | `d871b992e95b71c541ddc834f63c664b` |
| `subsdk0` | `84e50460493a12f26100e5150fbff271` |
| `sdk` | `d9add76fc264863d85fbbd1d70076c76` |

Do not bypass the profile's version or original-byte checks. The local `run_nxnative.py` wrapper contains machine-specific paths (`DEVELOPER_DIR`, `TOOLCHAINS`, `DOTNET_ROOT`, and its Python environment); review them before running it. Legacy experiment/archive scripts may depend on local apps, test saves, or NAS records not supplied here.

## Required input layout

All paths below are examples. Replace them with your actual generated files and run commands from the repository root.

| Input | Example path | Contents |
| --- | --- | --- |
| Clean original RomFS | `local-data/original-romfs/` | Directly contains `nativeNXx64/`, including both original font archives |
| Chinese overlay (Chinese build only) | `local-data/cn13/romfs/` | Directly contains `nativeNXx64/`; supply the overlay, not a merged game |
| Launcher settings | `local-data/build/launcher.json` | Generated settings for this title, including `DM_LANG` |
| Patched native host | `local-data/build/dmhost` | Built from the patched source for this game |
| Rewritten modules | `local-data/build/patched/` | Patched binaries and corresponding fixup tables |
| Compiled shaders | `local-data/build/msl/` | Matching `.metallib` files and supporting metadata |
| Profile tables | `local-data/build/tables/` | Matching shader map and other tables |
| Font substitutes | `local-data/build/font/` | `.ttf` files generated by the nxnative build |

`--base-romfs` requires an extracted directory, not `RomFS.img`. Export an image with the matching tools first if necessary. Do not use a Chinese app's already-overwritten resources as an original base: changing the language or removing a version tag cannot restore original files.

Inputs are kept unchanged. Each run copies a clean base into a fresh tree and applies an overlay only for the Chinese variant. Allow disk space for a full staging copy plus the packaged app. Existing outputs, symlinks, and conflicting path casing are rejected. The known CN1.3 font fingerprint is rejected as a base; this guard is not a comprehensive authenticity check. Keep all game data and prepared outputs in ignored local directories.

## Check inputs without writing files

Original, using the English defaults:

```sh
python3 scripts/build_variant.py \
  --variant original \
  --base-romfs local-data/original-romfs \
  --settings local-data/build/launcher.json \
  --prepare-only local-data/variants/original --dry-run
```

Chinese:

```sh
python3 scripts/build_variant.py \
  --variant chinese \
  --base-romfs local-data/original-romfs \
  --overlay-romfs local-data/cn13/romfs \
  --settings local-data/build/launcher.json \
  --prepare-only local-data/variants/chinese --dry-run
```

Remove `--dry-run` to prepare the copied RomFS, localized launcher settings, environment file, and variant report without compiling an app. The destination must not exist. Original builds reject `--overlay-romfs`; Chinese builds require it and reject an English game-language override.

## Package apps

Original with English gameplay and UI:

```sh
python3 scripts/build_variant.py \
  --variant original --language en-US --ui-language en \
  --base-romfs local-data/original-romfs \
  --settings local-data/build/launcher.json \
  --host local-data/build/dmhost \
  --patched local-data/build/patched \
  --msl local-data/build/msl --tables local-data/build/tables \
  --font local-data/build/font \
  --output 'release/The Great Ace Attorney Chronicles - Original.app'
```

Chinese with its default Chinese UI:

```sh
python3 scripts/build_variant.py \
  --variant chinese \
  --base-romfs local-data/original-romfs \
  --overlay-romfs local-data/cn13/romfs \
  --settings local-data/build/launcher.json \
  --host local-data/build/dmhost \
  --patched local-data/build/patched \
  --msl local-data/build/msl --tables local-data/build/tables \
  --font local-data/build/font \
  --output 'release/The Great Ace Attorney Chronicles - Chinese.app'
```

Add `--guide guide/guide.json` only if you want the supplied **Chinese-language, spoiler-containing** walkthrough. Without a guide, its menu entry is hidden. An optional `--icon PATH` supplies a local app icon. The output filename is your choice; the app's display name follows `--ui-language`.

Full packaging commands also accept `--dry-run`. They check input presence, variant/language constraints, and packer support; they do not compile, sign, or establish that every supplied artifact matches the game. Normal packaging builds the launcher, signs locally with an ad-hoc identity, and runs `codesign --verify --deep --strict`. Only a completed, verified bundle is renamed to the output path. Existing apps are not replaced or installed.

Both variants default to 1080p / 30 FPS / SDR and share resolution, frame-rate, and input features. `Contents/Resources/build-variant.json` records the variant, default game/UI languages, bundle/data IDs, and overlay file hashes. It contains no keys or personal saves. Local generated bundles contain user-supplied game assets: do not publish them as repository source or assume MIT covers them.

## Optional EDR experiment

Add the following argument to either packaging command if you already generated the matching experimental shader:

```sh
--edr-shader local-data/hdr-test/unclamp-msl/720e88a17ae787f6_b.metal
```

The shader is derived locally and is not included in this repository. Without it, EDR is not offered. With it, SDR remains the default and EDR is opt-in. EDR is experimental, not verified calibrated native HDR. Use only a shader matching the same Japanese game build; see the historical [graphics notes](native-display-target.md) in Chinese.

Do not run legacy `configure_fps_trial.py` or `configure_edr_trial.py` on these final outputs: they rewrite bundle/data IDs for older trial apps.

## Validation and manual checks

Run the tests without game assets:

```sh
python3 -m unittest discover -s scripts -p test_build_variants.py -v
python3 -m unittest discover -s scripts -p test_original_button_overlay.py -v
```

The native overlay suite requires macOS and the patched nxnative checkout; it compiles the overlay code with synthetic files and checks both original and Chinese cleanup behavior. The variant tests use artificial resources and simulated packaging, so passing them does not establish gameplay compatibility. English settings are checked even when the input JSON was previously Chinese, including optional EDR settings. The native launcher is compiled separately during development; compiler success does not verify visual fit or every interaction.

Before treating a local English build as ready to play, check the launcher on an English macOS setup, keyboard mapping, controller selection, save profiles, window skipping/Option reopening, and the in-game Launch Settings restart dialog. Then verify Japanese/English switching, title/menu text, voices, courtroom and investigation input, saving/loading, and longer gameplay. Complete both games' chapters and graphics stability remain unverified. Physical controller hotplug and external-display transitions also require hands-on testing.
